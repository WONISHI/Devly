## 1. 用户已确认的产品目标

**做一个具备 Codex 类似功能、能够接入第三方 API 的桌面 AI 编程工具。**

- 主路线改为 **Devly 自研 Agent 运行时 + 第三方模型 API 适配 + 本地工具执行**。
- 用户可以配置供应商、API 协议、Base URL、API Key、模型和必要参数。
- 不要求用户安装 Codex、登录 ChatGPT 或购买某个特定模型服务。Codex App Server 只保留为后续可选入口。
- UI 仍使用已指定的原版 AI Elements；Electron、React、TypeScript、Tailwind、Lucide、Zustand 等选择保留。
- 功能对齐按可操作的用户流程验收，模型质量取决于实际接入模型；不声称任意 API 都能执行所有 Agent 功能。

API 接入先覆盖 OpenAI-compatible Chat Completions，再覆盖 Responses 和 Anthropic 原生 Messages。它们是不同适配器，不根据服务商名称推断兼容性。模型必须通过对应工具调用和流式能力验证，才能用于完整编程任务。

### 当前限制

1. 项目只在内存中，重启不保留；无用户内容数据库。
2. 当前界面写着“Codex 尚未连接”，需要改为新的 Provider/Agent 概念；本轮只更新计划，不伪装为已实现。
3. 当前自动测试只有 1 项参数契约测试；现有桌面 smoke 不覆盖 Agent、审批、恢复或真实 Git 操作。
4. 本机 .app 未签名、未公证、不是 DMG；没有 Windows 或 Linux 运行验收。
5. 当前版本组合只完成搭建验证，正式发行前需要维护版本和兼容性审查。
6. 暂无第三方模型实际调用证据；真实联调依赖用户配置的有效端点与凭据，不能把测试替身当作已接通供应商。

## 6. 下一批具体执行顺序

当前文档任务完成后，下一次进入开发时按以下顺序推进；此处不代表这些功能已经开始。

1. **B03 + B02**：完成产品概念迁移和 Provider/Agent IPC 契约，确保 Codex 不是前置条件。
2. **L01 + L03 + L04**：先落地数据库、Provider 配置与凭据保存，避免只能临时填 Key 的演示。
3. **P01 + P02 + P03 + P04**：实现第一个可配置 API 的真实连接和流式响应。
4. **P05 + P06 + L05 + L06**：模型能力探测、会话数据和历史。
5. **U01 + U02**：用原版 AI Elements 把真实流式聊天接到桌面界面。
6. **T01 + T02 + T03 + A01–A04**：先建立只读 Agent 闭环，验证连续工具调用。
7. **T04–T08 + A06**：再接写文件、命令、权限、审批和取消。
8. **G02 + G03 + G05 + A09**：交付真实第三方 API 编程 MVP，再推进剩余核心与扩展能力。

关键用户凭据没有配置时，继续完成不依赖真实服务的实现与本地验证，并将真实 API 验收保留为待验证，不把“没有 Key”当作所有开发都不能推进。

## 7. 每项完成时必须记录什么

在 `work-log.md` 追加：日期、任务 ID、用户触发或需求、具体实现、涉及文件、验证命令/实际结果、人工场景结果、未覆盖范围、数据或权限影响、下一步。然后回到本表更新任务状态和日志编号。

已有任务开始时可在对应行补充状态说明及记录链接；任务 ID 不重排。新增任务只追加编号。取消或范围调整保留历史原因，不直接删除已经开展的工作。
