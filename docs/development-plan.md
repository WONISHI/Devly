# Devly 阶段与交付节点

更新：2026-11-26。按用户要求，开发改为逐阶段、逐步骤执行。

**唯一执行清单和状态来源是 [分阶段工作计划](./work-plan.md)。** 本文件说明交付节点，不再维护另一套阶段编号、任务顺序或完成状态；历史按模块分组的清单已归档。

## 1. 不变的产品方向

做具备 Codex 类似能力、能直接接第三方模型 API 的桌面 AI 编程工具。主路线为 Devly 自研 Agent + Provider 适配层 + 本地工具，不依赖 Codex CLI、ChatGPT 登录或 Codex App Server。

保留 Electron、React、TypeScript、用户指定的原 AI Elements 及配套 shadcn/ui、Tailwind CSS、Lucide 和 Zustand。已完成的基础工程与品牌资源不重复开发。

## 4. 推进与暂停条件

- 一次只推进工作计划中的当前阶段，依次完成表格步骤和阶段验收，再更新位置进入下一阶段。
- 不因看到另一个容易任务就跨阶段开发；可以查阅后续接口，避免设计矛盾。
- 当阶段内某项缺少 Key、端点、目标平台或签名条件时，记录具体缺失条件，继续本阶段其他独立准备工作；受影响的验收保持待验证或受阻。
- 阶段验收通过即可按计划继续，不额外设用户批准流程；真实凭据、平台或需求缺失仍需如实处理，不能把时间经过当作授权。
- 阶段 6 的可写工具在权限、审批和取消一起验收前不向用户启用；阶段 9 的跨重启继续在 R02 验收前不可用。
- 每项完成后追加 [工作日志](./work-log.md)，记录步骤号和稳定任务 ID。阶段编号可随用户要求调整，历史 ID 不重排。
