# Provider / Agent 入口与界面收敛（B03）

更新：2026-11-22。B03 首次验收见 LOG-012；用户要求清理工程演示内容后的修正见 LOG-013。这里记录当前实际界面。

## 当前界面

- 首页为任务空状态：任务标题、输入占位、项目选择和模型选择；侧栏保留新任务、项目及底部设置。
- 不再在首页显示开发环境、技术栈、阶段说明、组件演示入口、PREVIEW/LOCAL 标签、UTF-8/TypeScript 状态栏或重复的未实现说明。
- 首页“选择模型”打开原版 AI Elements ModelSelector，显示已保存模型、供应商与端点域名，可搜索和键盘选择；同名模型按供应商分组，不会混淆。未打开项目时保存应用默认值，打开项目后保存当前项目默认值；已有会话另保存独立绑定，有历史时切换须明确选择保留历史或新建会话，重启后恢复。没有模型时可进入添加供应商；有配置时提供管理供应商入口。侧栏设置仍支持供应商编辑、原生密钥与连接检查，Key 不进入 Renderer。
- 设置按“模型供应商、外观、默认模型、权限与限额、开发者”分组，左侧分类切换右侧独立内容，任一时刻只显示对应组。草稿跨分类保留；应用/当前项目范围仅在偏好分类显示，保存仅提交当前分类字段，导出仍读取本范围全部已保存偏好。模型供应商的编辑/连接状态隐藏保留，开发者页只显示诊断与组件预览。
- 环境检查和原 AI Elements 演示保留在设置页默认折叠的“开发者选项”；关闭组件预览返回设置，再返回工作台。
- 页面切换保留项目与环境内存状态；项目名只在需要的位置显示，完整路径放在侧栏项目的 title 提示中。
- 原 Prompt Input 可编辑、发送与停止，消息用原 Conversation/Message 展示；选择项目和模型后可普通聊天，历史分页和重启恢复已接入。附件按钮明确禁用，Agent 工具执行未实现。

## 系统边界

正常环境查询只读取应用运行时和 Git；没有 Git 时仍能启动和导航。正常启动不探测 Codex，也不读取 DEVLY_CODEX_PATH。独立 verify:codex 仅是可选技术脚本；v1 的 codex 字段保留，正常查询固定为 null。

阶段 2 已实现受保护凭据、设置持久化和会话元数据；阶段 3 的供应商编辑与模型诊断已落地，本地测试通过，真实端点验收仍待完成。见 [本地数据说明](./local-data.md) 和 [Provider API](./provider-api.md)。Agent 执行仍属后续阶段。

## 验证

pnpm check 覆盖静态检查、契约测试、原组件完整性与生产构建。pnpm verify:desktop 检查首页精简、设置导航、开发者折叠状态、环境刷新、原组件预览、项目取消/错误/选择和返回状态；另外检查 960×680 内容区无横向溢出。

pnpm verify:no-codex 为子 Electron 创建空 PATH，实际执行 codex --version 并要求 ENOENT，再走真实 IPC 与界面检查，不替换环境响应或修改开发机 PATH。两者均支持 DEVLY_EXECUTABLE 指向打包程序。

macOS 的实际结果见工作日志；Windows 和远端 CI 未因此获得通过状态。

LOG-034 的 pnpm verify:model-picker 检查新增配置立即可选、搜索/键盘/Escape、同名供应商模型、两次重启与项目隔离、模型改名后保留明确旧选择、删除后清空失效选择。仅选择模型不向端点发请求，未实现的协议/空模型禁用；没有将默认模型选择等同于会话绑定或真实聊天。

阶段 4 的绑定、运行时与输入/历史已落地，见 [普通聊天说明](./chat.md)。本地 HTTP 桌面检查通过；真实端点仍待正常凭据环境联调，不将普通聊天称为完整 Agent。
